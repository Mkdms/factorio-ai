## 1. 联机重连 / 崩溃恢复

- **V1P-1** 判断游戏崩了 → 看游戏日志 (factorio-current.log) 末尾 4000 字节有没有 "Factorio crashed" 或 "Unexpected error occurred"; 同时状态读不到 (没挂上, 或状态不是 游戏中 / 主菜单 / 暂停) 连续 45 秒才触发恢复, 两次恢复至少隔 5 分钟 → 崩溃报告每次崩溃只写一次; 短暂读不到不算崩。〔pilot/src/game/recovery.ts 32-42; pilot/src/main.ts 312-327〕待核实
- **V1P-2** 联机服务器 (协助模式) 上游戏进程没了 → 只告警, 让人手动重开并连回, 绝不读本地存档 → 别人的世界不能用本地档顶替。〔pilot/src/main.ts 319-323〕待核实 (规则)
- **V1P-3** 单机崩溃恢复 → 杀掉游戏进程 → 经 Steam 拉起 → 等进程出现 (最多 3 分钟) → 再等 25 秒 → 挂接并要求到主菜单 (最多 2 分钟) → 点 "单人游戏" → "载入存档" → 点最新的 `_autosaveN` → "加载" → 最多 160 秒等进入世界 → 中文菜单按钮文字 2026-10-28 在 2.1.24 手动核实过; 坑: 按进程名杀会把同机另一个客户端一起杀掉, 要按 pid; 数据导出进程也叫 factorio.exe, 挂接报出多个 pid 时逐个试。〔pilot/src/game/recovery.ts 1-3, 178-225; pilot/src/main.ts 267-291〕待核实
- **V1P-4** 选哪个存档 → 按修改时间取最新的 `_autosave<N>.zip`, 跳过 `.tmp` (写了一半的) → 存档列表若自动选中了 .tmp 会弹 "文件无效或损坏", 要先点确认再选; 关提示框 = 找 NoticeBox / ModalDialog / ConfirmDialog / MessageBox 下的按钮, 优先 确认 / 确定 / 关闭 / 好 / 是 / OK / Close, 没有就点最后一个。〔pilot/src/game/recovery.ts 44-53, 82-105〕待核实
- **V1P-5** 联机掉线怎么判 → 协助模式下世界未加载、停在主菜单超过 20 秒就算掉线, 重连 2 分钟最多一次 → 读图和切换也会短暂回主菜单, 20 秒是防误判。〔pilot/src/main.ts 329-336〕待核实
- **V1P-6** 重连步骤 → ① 界面上有 "下载地图 / 正在连接 / 正在载入" 之类文字 = 客户端自己在重连, 等约 30 秒再看; ② 否则点掉线对话框的 "重新连接"; ③ 没有就 "多人游戏" → "连接到地址" (上次地址已预填) → "连接"; ④ 每 4 秒读一次状态, 最多 3 分钟等进入世界, 期间顺手关提示框 → 游戏自带的重连比手点快, 别抢。〔pilot/src/game/recovery.ts 116-176〕待核实
- **V1P-7** 自动存档时注入的 Lua 查询会把游戏弄崩 (2026-10-28 一次: LuaValueSaver::save → invalid index, 当时查询每秒 6~10 次) → 预测下一次自动存档, 存档前 5 秒到存档后 6 秒不和游戏通信, 窗口前 1.5 秒松开全部按键 (发一条空时间线) → 预测法: 日志里出现 "Saving to _autosaveN" 就以这一刻 + 间隔 (第一版写死 300 秒, 应读游戏设置) 为下一次; 刚读档时用日志首行的墙钟时间 + "Loading map" 行的秒偏移算读档时刻, 自动存档计时从读档那一刻起算; 窗口过去 2 秒还没见到存档行就顺延一个间隔。〔pilot/src/game/saveguard.ts 1-3, 28-57, 107-142〕待核实 (崩溃原因未证实; 这是预测不是检测)
- **V1P-8** 长按键和存档窗口重叠 → 一条输入时间线的时长 = 最后 tick/60 秒 + 0.2 秒, 开始时刻 + 时长落进窗口就先等 → 一条 5 秒的挖矿按键在存档前 4 秒开始, 存档时仍在跑。〔pilot/src/game/saveguard.ts 79-105〕待核实
- **V1P-9** 世界暂停 (单机科技窗口 / ESC 菜单) → 输入会直接失败, 第一版等世界恢复最多 15 分钟再继续 → 人可能正在看科技树, 不能当成错误放弃任务。〔pilot/src/mcp/input.ts 105-120〕待核实
- **V1P-10** 怎么判角色死了 → 玩家从 "有角色" 变 "无角色"、且世界已加载超过 60 秒才算死亡 (游戏把玩家切到幽灵控制器直到复活) → 重连和读图时这个标志也会翻, 没有 60 秒门槛会误计死亡。〔pilot/src/game/stats.ts 72-90〕待核实

## 2. 寻路的坑

- **V1P-11** 管线之间的缝 → 角色碰撞盒 ±0.2 格, 管道 / 墙壁 ±0.29, 相邻两根之间 0.42 格的缝纸面上能过、游戏里过不去: 算路时把角色盒子再加 0.05 当墙; 电杆、机械臂 ±0.15, 它们之间的缝人能过, 不能整格封死 → 整格标记会把每条管线当成墙 ("所有方向都被挡"); 用半格网格 (格心既在地块中心也在地块边) 配真实碰撞盒。〔pilot/src/skills/path.ts 94-95, 157-184〕待核实
- **V1P-12** 什么挡人 → 按原型碰撞层算: 实体 collision_mask 和角色层 (player / train / is_object) 有交集就挡 → 手写的 "可过" 表两头都错过: 闸门被当成墙 (实际会给人开门, 可过), 铁轨支架、铁轨坡道被当成能过 (实际挡); 热管、传送带、铁轨、地上物品、尸体、幽灵、地雷可过; 移动的东西 (虫、车、角色) 不当墙, 用危险圈处理。〔pilot/src/skills/path.ts 8-42〕待核实
- **V1P-13** 悬崖 → 接口给的悬崖碰撞盒是细条, 相邻段之间约 0.6 格的 "缝" 游戏里过不去; 悬崖四周多标 1 格, 让整条悬崖成一堵墙 → 曾贴着悬崖推了 2 分钟。〔pilot/src/skills/path.ts 246-252〕待核实
- **V1P-14** 铁轨 → 人能走铁轨, 但沿着走会被火车撞死 → 铁轨格代价 ×8 (只垂直横穿不沿走), 简化捷径也不许经过铁轨格。〔pilot/src/skills/path.ts 88, 224-240, 394-395, 478-495〕待核实
- **V1P-15** 水和未生成区 → 地块 collision_mask 含 player 的当水 (不可走), 未生成的地块也当墙 → 穿机械装甲 (原型 provides_flight) 时水、悬崖、建筑、树都不挡 (飞行时角色碰撞层只剩 trigger_target), 只有地图外 / 太空地块仍挡, 这时也省掉全部实体查询。〔pilot/src/skills/path.ts 125-137, 185-198, 222-253〕待核实
- **V1P-16** 读取被截断 → 实体按 64×64 页读, 一页满 512 条就四等分再读 (到 8×8); 地块按 128×128 页; 类型名每批 ≤64 个 → 密集区 (太阳能板、机械臂行、森林) 一页超 512 条, 截断会静默漏掉建筑, 路线直接穿过去; 页缓存 实体 60 秒 / 地块 5 分钟, 未缓存的读之间隔 40 ms 不连发。〔pilot/src/skills/path.ts 100-114, 199-230〕待核实
- **V1P-17** 危险圈 → 2 小时内的死亡点画 30 格禁圈; 当前看到的敌人: 虫巢 32 格、重踏 / 飞弹五足虫 / 大型 / 巨兽型 28 格、其它 18 格; 起点或终点已在圈内就不画 → 死亡 6 是绕路时直接走进 6 只五足虫。〔pilot/src/skills/path.ts 254-278〕待核实
- **V1P-18** 网格范围和目标 → 边距 = max(12, min(48, 距离/3)) 格 (长途要绕湖绕林), 网格最大 192×192 (铺带子 256); 目标格被实体占着就停在相邻格; 容差 ≥1.5 时在目标周围找最近的空格 (最多试 24 个) → 岸边的锅炉这种被管子和水围住的也能走到。〔pilot/src/skills/path.ts 139-156, 352-408, 417-469〕待核实
- **V1P-19** 走直线的步长 → 按住方向键, 每段 tick 数 = (剩余距离 − 容差/2)/速度, 限 6~90 tick; 8 向键: 方向分量 >0.38 才按那个键 → 速度必须实测 (每段位移 / tick, 限 0.05~1), 不能按 0.14 假定: 游戏数据跑速 0.15 格/tick, 每个外骨骼模块 +30%, 机械装甲飞行更快; 按 0.14 预算让穿外骨骼的角色冲过头约 2 倍, 25 格走了 64 段。〔pilot/src/skills/move.ts 184-242〕待核实
- **V1P-20** 卡住判定 → 一段位移 < min(1, tick×速度×0.25) 算卡; 卡了就垂直于前进方向侧移 (12 + 6×次数 tick, 左右交替); 直走 3 次卡住放弃, 沿规划路径走时 2 次就放弃 (侧移会把人挤到下一栋建筑上) → 一段用时超过预计 3 倍 (8~120 秒) 算超时: 贴悬崖滑行不算 "没进展", 曾推 2 分钟。〔pilot/src/skills/move.ts 203-256〕待核实
- **V1P-21** 卡点记忆和分段 → 卡住的格子 (前方 0.9 格及两侧) 记 15 分钟当障碍 (网格里没有的新建筑、石头、植物), 重规划最多 5 次; >28 格先规划再走; >110 格分段, 每段 90 格, 直走不通就往两侧偏 40 / 80 格试, 最多 16 段 → 几百格的长途要一段一段看地形, 绕开水和悬崖。〔pilot/src/skills/move.ts 53-77, 103-182〕待核实
- **V1P-22** 出门的安全规则 → 目的地 40 格内有敌方单位 / 虫巢 / 沙虫就拒绝 (死亡 14: 自动巡检把人派到墙外的炮塔); 路上反射层撤退过 ("打不过") 这趟作废, 不得换条路再去同一目标 (死亡 6: 撤退后又走回去, 原地转圈); 角色没了立刻停 (曾对着死掉的角色按了半分钟方向键)。〔pilot/src/skills/move.ts 37-51, 79-86, 219-229〕待核实
- **V1P-23** 铺带子的路线 → 4 向 A* 带朝向状态, 转弯代价 4 格, 不原地掉头 → 带子尽量直、只在必要处拐; 早先每格 0.3 的转弯代价把斜线走成楼梯。〔pilot/src/skills/path.ts 282-334〕待核实
- **V1P-24** 传送带把人运走 → 第一版里没有这块 (传送带只是在 "可过" 表里, 没考虑站上去会被带走)。〔pilot/src/skills/path.ts 34-42〕

## 3. 开车

- **V1P-25** 上车 → 走到载具 2.2 格内, 按 "上下车" 键 (默认回车) 4 tick, 等 250 ms 读 driving 标志, 最多 3 次 → 要在 2 格内按才有效; 失败多半是太远或车里有人; 载具类型 car (汽车、坦克) 和 spider-vehicle (蜘蛛机甲), 蜘蛛机甲没有单独处理 (第一版里没有这块)。〔pilot/src/skills/drive.ts 12, 58-75〕待核实
- **V1P-26** 下车 → 先按后退键 20 tick 刹停, 再按上下车键, 最多 3 次读回 → 从开动的坦克跳下会受伤。〔pilot/src/skills/drive.ts 77-90〕待核实
- **V1P-27** 怎么开 → W 加速、S 刹车 / 倒车、A / D 转向; 朝向 0~1 顺时针从北, 期望朝向 = atan2(dx, −dy)/2π; 误差 >0.02 就转, 转向按键 tick = min(11, |误差|×160); |误差| <0.12 算对准才给油; 每 12 tick 读一次位置 / 朝向 / 速度再决定下一段 → 坦克能原地转, 汽车要有点速度才转; 盲按一段会直接撞楼。〔pilot/src/skills/drive.ts 1-3, 154-171〕待核实
- **V1P-28** 速度 → 上限 0.35 格/tick (约 75 km/h), 坦克极速约 0.56; 目标速度 = min(上限, max(0.06, 距离/60)); 速度 >0.12 又没对准先刹 6 tick; 障碍 5 格内降到 0.12 → 太快转不过来; 坦克高速撞上什么就毁掉什么。〔pilot/src/skills/drive.ts 119, 164-169〕待核实
- **V1P-29** 惯性 → 一段 12 tick 走 速度×12 格, 松键后继续滑行; 最后一段距离 < max(容差+1, |速度|×30) 时就开始刹; 刹车中越刹越远且在容差+6 内就算到 → 实测容差 2 时冲过目标 4.6 格。〔pilot/src/skills/drive.ts 144-153〕待核实
- **V1P-30** 车卡住 → 对准且一段位移 <0.15 连续 4 次算卡; 3 格内有障碍 (基地里) 不硬撞, 停车把决定交回 (清障或换目标); 否则倒车 24 tick + 反打方向 18 tick, 把卡点加进障碍重新规划; 到达判定 容差+2, 超时 240 秒, 最多 600 段。〔pilot/src/skills/drive.ts 173-208〕待核实
- **V1P-31** 车的路线 → >20 格才规划; 障碍四周膨胀 2 格 (坦克比人宽, 擦到建筑就毁); 航点每 3 个取 1 个 (重规划后每 6 个) → 车能切弯, 航点少开得顺; 没有留 2 格余量的路线就不开, 换目标或先清障。〔pilot/src/skills/drive.ts 112-128, 212-220; pilot/src/skills/path.ts 417-439〕待核实
- **V1P-32** 车上遇敌 → 坐车时只开火不按方向键 (方向键会把坦克开进建筑), 坦克 2000 血 + 护盾靠车扛; 规则: 坦克只当装甲出租车 (冲进去拿东西 / 放幽灵再出来), 普通炮弹打不动五足虫; 车血 <1200 立刻回炮塔群; 下车前 40 格内不能有重踏 / 飞弹五足虫或大型; 基地有坦克 / 汽车 / 蜘蛛机甲就开着去, 不徒步走远路。〔pilot/src/reflex/combat.ts 92-107; pilot/src/brain/agent.ts 63-64〕待核实
- **V1P-33** 车和禁区 → 开车的目标也受死亡禁区约束 → 死亡 5 是坦克本身在禁区里被打爆。〔pilot/src/skills/index.ts 242-246〕待核实

## 4. 战斗

- **V1P-34** 扫描节奏 → 反射层 150 ms 一轮, 空闲时每秒只扫 1 次; 交战半径 22 格, 重型 (重踏 / 飞弹五足虫、大型、巨兽型、撼地虫) 从 60 格外就算威胁; 每段按键 18 tick; 弹药 3 秒读一次, 装备 1 秒读一次 → 每次查询占游戏一帧, 约 10 次/秒会让客户端 UPS 掉到 60 以下, 联机会跟不上服务器 (掉心跳、断线); 重型 20 格约 2 秒就到; 按键段要长于轮询周期才连续。〔pilot/src/reflex/combat.ts 27-29, 73-112, 190; pilot/src/config.ts 67〕待核实
- **V1P-35** 小虫 → 撕咬虫都比人快 (小型 12 格/秒 vs 角色 9), 不风筝, 站桩打; 受伤跑向最近的机枪炮塔 (射程 18, 10 发/秒) 或家 → 沙虫 (射程 25~48) 和虫巢从不主动打, 只有沙虫在 30 格内时背离它退 12 格且不开火。〔pilot/src/reflex/combat.ts 27-29, 114-119, 261-272〕待核实
- **V1P-36** 撤退 → 血 <40% 撤; 滞回: 一旦撤退, 血回到 70% 以上 (且至少 4 秒) 才停; 安全点 = 64 格内 "不比自己更靠近敌人" 的最近己方炮塔 (机枪 / 激光 / 火箭 / 特斯拉 / 火焰都算) 背离敌人 6 格处, 没炮塔就回家; 撤退方向 = 背离敌群, 向安全点拉 (安全点不在敌人那侧时) → 原来锚在开战点 (墙外), 人就在墙外绕圈。〔pilot/src/reflex/combat.ts 29, 132-142, 169-171; pilot/src/main.ts 106-120; pilot/src/reflex/combat-model.ts 133-141〕待核实

## 6. 热管口 / 机械臂吞吐

- **V1P-48** 热口怎么对 → 口在实体自己的某格 (position) 上朝 direction, 它连的是 "position + 朝向一步" 那一格里的实体, 对方在那格必须有朝向相反 ((d+8)%16) 的热口; 热管四面都有口; 实体转向 d 时, 口的位置顺时针转 d/4 个 90° ((x,y)→(−y,x) 每次), 口朝向 = (原朝向 + d) % 16; 方向编号 0 北 4 东 8 南 12 西 (16 分) → 第一版不写死核反应堆 / 供热塔的口位, 一律从原型读: energy_source.type=heat 的 connections (换热器, 属 boiler 类) 和 heat_buffer.connections (核反应堆、供热塔, 属 reactor 类)。〔pilot/scripts/extract-entity-ports.mjs 90-91, 158-161; pilot/src/skills/port-check.ts 243-259〕待核实
- **V1P-49** 热网检查 → 换热器热口一个都没接 = 错; 热管四面都没接 = 错; 一片热网有换热器却没有 reactor 类热源 = 错 → 教训: 一座电站的换热器全是干的, 起因就是热管 / 管路没接上。〔pilot/src/skills/port-check.ts 1-2, 260-270〕待核实
- **V1P-50** 流体口 → 同样的 "位置 + 反向口" 规则, 再加类别交集 (没写 = default); 地下管道的地下口沿朝向找第一个同名实体的反向地下口, 距离 ≤ max_underground_distance (地下管道 10); 两个输入口 (或两个输出口) 对着 = 流体不流; 配方的流体按顺序分配口 (第 1 种液体原料进第 1 个输入口), 写了 fluidbox_index 就固定那个口; 有 fluid_boxes_off_when_no_fluid_recipe 的机器在无流体配方时口不存在; 一张管网只能一种流体, 每个用户要有来源 (抽取泵或输出口); 管道单头空着: 网里有来源也有用户 = 无害多余头, 否则是断线。〔pilot/src/skills/port-check.ts 147-241; pilot/scripts/extract-entity-ports.mjs 159-163〕待核实
- **V1P-51** 机械臂取放 → pickup / drop 是相对中心的偏移, 朝向 0 时取北放南, 机械臂 direction = 取货方向; 取放位置上必须有物品栏 (箱子、机器、炉、研究中心、炮塔、带子、车、着陆台、燃烧器…), 空地或没物品栏的实体 = 错。〔pilot/scripts/extract-entity-ports.mjs 162; pilot/src/skills/port-check.ts 78, 272-286〕待核实
- **V1P-52** 机械臂每秒搬多少 → 一次摆动 (取→放→回) = 一整转 = 1/rotation_speed tick, 每秒摆动 = 60 × rotation_speed × 0.95 (两头停顿按 95% 折: 1.1 wiki 快速机械臂箱到箱 2.31/秒 vs 按转速算 2.4); 每次搬 = 手大小 = 1 + 机械臂容量研究 (批量机械臂 1 + 批量容量研究 + 自身 stack_size_bonus), 不超过物品堆叠上限; 从带子取货再折: 手 >4 件 ×0.5, 否则 ×0.85 (逐件捡, 保守); 每秒件数 = 摆动 × 手 → 例: 无研究、rotation_speed 0.014 (代码默认值)、手 1 → 0.80 次/秒 ≈ 48 件/分钟, 和第一版布局注释 "普通机械臂约 0.8 板/秒、石炉 0.31 板/秒" 一致; 各型号 rotation_speed 要从 2.1.24 原型读。〔pilot/src/skills/port-check.ts 339-357; pilot/src/skills/layouts.ts 170〕待核实
- **V1P-53** 机器吃多少 → 每秒合成 = crafting_speed × (1+速度加成) / 配方时间; 原料 = 用量 × 合成数, 产物 × (1+生产力); 信标效果 = 信标里模块效果 × distribution_effectivity × profile[同时作用的信标数 −1] (2.0 递减); 送料 / 出货臂每秒摆动 < Σ 用量 / min(手, 堆叠) = 错, 按需生产的机器 (建材厂) 只是封顶 → 警告 → 燃烧器燃料 = energy_usage × (1+耗能加成) / (燃料值 × effectivity), 供热塔 = consumption / (燃料值 × effectivity); 教训: 一台燃烧机械臂喂不动 40 MW 供热塔。〔pilot/src/skills/port-check.ts 339-346, 364-376, 401-449〕待核实
- **V1P-54** 流体网核算 → 换热器 水 = 蒸汽 = 能耗 / (蒸汽热容 × (500 − 15)) (10 MW 时约 103/秒); 汽轮机 fluid_usage_per_tick × 60 = 60 蒸汽/秒; 抽取泵 pumping_speed × 60 (默认 20/tick = 1200/秒); 来源 < 用户 = 错, 蒸汽例外 (每台换热器配 2 台汽轮机、跑不满是有意的, 只警告); 物流机器人台数 = 流量 × 2 × 到最近存储箱距离 / 速度 / 载量 (速度 ×(1+机器人速度研究), 载量 1 + 载量研究)。〔pilot/src/skills/port-check.ts 346, 413-417, 451-513〕待核实
- **V1P-55** 传送带检查 → 前一格带子反向 = 对头 (错); 尽头顶着机器 = 物品停在那里 (警告); 一格带子后面没有同向带且只有一侧汇入 = 弯道, 否则是侧向汇入; 地下带入口沿朝向 max_distance (默认 5) 格内要有同向出口。〔pilot/src/skills/port-check.ts 288-318〕待核实
