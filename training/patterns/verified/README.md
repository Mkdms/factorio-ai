# 思路库 (老玩家怎么想、怎么选)

> 2026-11-01 起。知识库里的 `facts.md` 是"事实和数值"; 这里放的是**思路**: 什么阶段该上什么、哪里该用什么建筑、事情之间怎么牵连、为什么有人这么建而不那么建, 以及与众不同的流派。
>
> 每条都是从老玩家的资料、联机服务器的基地或开发者的设计意图里整理的, 注明来源; 思路不是单条事实, 核实靠沙盘里把两种做法并排跑比 (架构第 4 节"设计搜索")。没比过的标"待核实", 设计师只能把它当候选, 审查员用它挑毛病。

## 条目格式 (所有文件统一)
```
### P-<主题>-<序号> <一句话标题>
- 情况: 什么阶段 / 星球 / 前提条件下
- 做法: 老手怎么做 (建筑、布局、顺序、数量级)
- 为什么: 背后的机制或经验 (能引用 facts.md 的编号就引用)
- 代价 / 不适用: 什么时候别这么做, 换成什么
- 关联: 这个决定和哪些别的决定牵连 (前置、后果、连锁)
- 流派: 通用 / 主线 / 城市块 / 火车网 / 机器人基地 / 寿司带 / 其他 (写清适合的阶段和条件)
- 出处: 网址 + 日期 + 版本 + 可信度 1~4; 或 "联机服务器的新地星基地 (2026-10-31 导出, 本人同意参考; 原因是推测)"
- 状态: 待核实 / 沙盘对比过 (实验编号) / 被推翻
- 沙盘怎么比: A 方案 vs B 方案, 看什么指标
```
