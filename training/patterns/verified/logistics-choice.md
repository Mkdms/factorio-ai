### P-logi-01 三种地面运输按距离和量分工: 带子 500 格内大宗流、火车远距离高吞吐、机器人只做密集局部
- 情况: 任何星球、任何阶段选运输方式
- 做法: 传送带 ≈ 500 格以内的大宗流 (一条超速传送带 60/秒, 堆叠后 240/秒); 火车 = 远距离高吞吐 (一节货运车厢 40 格, 传说 100 格); 机器人 = 密集的局部网 (车站内部、超市、研究区), 不适合远距离、运矿、喂熔炉; 量级参考: 每分钟 3000 件, 50 格要约 300 台机器人, 500 格要约 3000 台 (P34)
- 为什么: 机器人吞吐受机器人指令平台充电位限制 (每位 500kW, L8); 大而凹的网机器人扎堆延误 (L12); UPS: 远距离传送带最省, 火车不如传送带, 机器人很差 (P35)
- 代价 / 不适用: wiki 运输教程没写堆叠传送带和高架铁路, 数字偏旧 (P34); 后期几条堆叠超速传送带的吞吐超过上千台传说机器人 (L12), 但那是大基地的事
- 关联: 分界点随科技移动: 堆叠机械臂 + 传送带容量 2 (要先研究机械臂运力加成 7, 2.1.15) 把"带子够用"的范围拉大; 高架铁路 (紫瓶可研) 让火车能跨水/沼泽/油海 (P-logi-15)
- 流派: 通用
- 出处: P34 (wiki 运输用例教程 https://wiki.factorio.com/Tutorial:Transport_use_cases 2025-12-10, 2); L11 (wiki 物流网 2026-01-18, 2); L12 (论坛 t=125774 2025-01, 3); L8 (wiki 机器人指令平台 2026-03-16, 2); P35 (Reddit 摘要 约 2025-08, 3); facts belts.throughput.* (✅ 15/30/45/60)
- 状态: 待核实 (带速已核实, 机器人台数未核)
- 沙盘怎么比: 每分钟 1800 铁板运 100 / 300 / 600 格, A = 传送带, B = 机器人 (算需要几台 + 几座机器人指令平台), C = 1-2 列车; 比材料、铺设时间、稳定吞吐

### P-logi-02 车站两头在同一张机器人网里: 卸货进普通箱或红箱, 装货用蓝箱, 紫箱只用在独立网; 机车燃料例外
- 情况: 火车站落在机器人物流网覆盖范围内 (最常见于城市块)
- 做法: 卸货站出口用钢箱 (物流机器人不碰普通箱) 或被动供货箱（红箱）(最后一档才被取); 装货站用优先集货箱（蓝箱）; 主动供货箱（紫箱）只放在自成一网的小区; 高吞吐车站最好自成一张小网, 网间用火车/传送带/箱对箱接力 (L3); 但给机车加燃料的蓝箱 + 机械臂接主网没问题 (T18)
- 为什么: 机器人取货先找紫箱、不看远近 (facts logistics.pickup.active-provider-first ✅: 30 格外紫箱先于 1 格内红箱); 黄箱和绿箱同档按远近 (facts logistics.pickup.buffer-before-storage: 游戏内提示"绿在黄前"被推翻, wiki 对); 机器人不从钢箱取货 (facts logistics.pickup.ignores-plain-chests ✅); 第一版就是卸货进紫箱, 货马上被搬回装货站 (lessons #1)
- 代价 / 不适用: 卸进钢箱就断了机器人网的"自动分发", 要靠传送带/机械臂往下走; 2.1 没有改取货规则 (changes-2.1 第 4 节), 2.0 的经验照用
- 关联: 决定了城市块内"机器人只做块内"(P-logi-03); 决定了审查规则 "车站两头属于同一张网就报错, 卸货箱不是普通箱/红箱也报错"; 联机服务器的新地星基地车站两头用普通箱 (facts 关联)
- 流派: 城市块 / 火车网 / 机器人基地
- 出处: L1 (wiki 物流网 https://wiki.factorio.com/Logistic_network 2026-01-18, 2); L2 (wiki 紫箱 2025-05-27 + 论坛 2024-10, 2/3); L3 (论坛 p=629618 2024-10 + Reddit 摘要 2020, 3, 后者可能过时); T18 (论坛 p=690498 2026-03-22, 3); facts logistics.pickup.* (2.1.24 / 2026-10-31)
- 状态: 三条取货规则沙盘对比过 (facts 三条); "分网后卸下的货不再被搬走"待核实
 | 第九批补核实: 紫箱会被搬空进黄箱而红箱不动 (logistics.active-provider.emptied-to-storage), 绿箱只给勾了"允许从主动存货箱取货"的蓝箱 (logistics.dispatch.buffer-only-to-opted-in-requesters), 黄箱存入顺序 过滤 > 同种 > 空 > 杂物 (logistics.storage.insert-order)
- 沙盘怎么比: A = 卸货站在主网内卸进红箱, B = 卸进紫箱, C = 车站自成小网卸进紫箱; 跑 30 分钟数"卸下又被搬走"的件数

### P-logi-03 机器人网怎么分区: 让物流范围不重叠就是两张独立的网, 块间靠边缘箱子或火车接力
- 情况: 城市块或多区域基地
- 做法: 相邻区的机器人指令平台橙色 (物流) 范围不重叠 = 两张网, 机器人留在各自的网里; 建设 (绿色) 范围可以重叠; 块间转运靠块边缘的箱子 (一边红箱、一边蓝箱 + 机械臂) 或列车 (ML23); 车站区自成小网 (L3); 玄冥星只在商场/发射井/科研几块小区放机器人 (A28)
- 为什么: 机器人在大网里会跨整张图去取紫箱 (L2: 200 格外的紫箱先于 20 格内的红箱); 分网把"取货不看远近"的副作用关在一块里
- 代价 / 不适用: 分网后每个网都要自己的建材/修理包供应 (或由建设范围重叠的那张网修); 已知边缘情况: 新块的机器人指令平台比电线杆先建好、没电时, 建设机器人会换网络 (ML23) → 先铺电杆再放平台
- 关联: 分网大小 ≈ 城市块尺寸 (机器人指令平台物流半径 25 → 50 格宽, layout-styles.md P-style-03); 命名物流组全图共享, 改一处处处变 (L7)
- 流派: 城市块 / 机器人基地
- 出处: ML23 (Steam/论坛摘要 2019 ~ 2022, 3, 可能过时); L3 (论坛 2024-10, 3); L2 (wiki 2025-05 + 论坛 2024-10, 2/3); A28 (Steam 2025-01-20, 3); L7 (wiki 2026-01-18, 2)
- 状态: 待核实 (research README 第三轮建议: 验证"物流范围不重叠 = 独立网")
- 沙盘怎么比: 两块各一座机器人指令平台, A = 物流范围刚好不重叠, B = 重叠 1 格; 一边放紫箱一边放蓝箱, 看机器人跨不跨

### P-logi-04 会孵化的东西只走传送带: 五足虫卵、异虫卵不进机器人网、不上火车, 多的烧掉
- 情况: 句芒星卵线; 新地星虫巢孵化器区; 钷素船
- 做法: 五足虫卵的带子顺序 = 繁殖 → 农业科技包 → 造生物室 → 末端供热塔烧掉 (G10); 异虫卵: 两个虫巢孵化器常备约 1000 个新鲜卵, 旧卵扔出去烧掉 (D14); 卵不进箱子存放, 不放进蓝箱/紫箱, 不上火车; 要"存卵"就存成生物室 (回收 25% 返卵, G10) 或产能插件 3 / 沃土 (ER8)
- 为什么: 五足虫卵 15 分钟后在原地孵出大型早衰蠕动五足虫, 一个卵一只 (facts spoilage.pentapod-egg.hatches-15-minutes ✅); 异虫卵 30 分钟孵出大型撕咬虫 (D14, L6); 机器人网和火车里的卵会在看不见的地方孵化; 会孵化的东西只走传送带这条规矩就以此为根据
- 代价 / 不适用: 钷素船必须把异虫卵带到星系边缘以外 (配方要重力 0), 只能用平台枢纽运, 卵在枢纽里也会孵 → 船要在 30 分钟内用掉 (ER9: 往返略少于 40 分钟, 卵过期前约能做 25 分钟)
- 关联: 孵化风险处全摆朝内的炮塔 (defense.md P-def-12); 供热塔满温照烧正好当垃圾桶 (L22; facts power.heating-tower.burns-at-max ✅)
- 流派: 直塞 / 短带 (句芒); 通用
- 出处: G10 (Steam 2024-11-29, 3); D14 (B 站专栏 2025-05-13 + wiki 异虫卵 2026-05-20, 3/2); ER8 (wiki 钷素科技包 2026-09-28, 2); ER9 (论坛 p=694866 2026-06, 3); L22 (论坛 p=690149 2026-03, 3); facts spoilage.pentapod-egg.hatches-15-minutes (2.1.24 / 2026-10-31)
- 状态: 孵化事实已核实; "生物室回收返卵 25%" 待核实
- 沙盘怎么比: A = 卵线末端接供热塔, B = 卵线末端接钢箱; 20 分钟后数孵出的虫和被毁建筑

### P-logi-05 会腐坏的东西: 运果子不运果泥, 现场加工、短带或直塞, 不囤; 机器人和带子都不看新鲜度
- 情况: 句芒星任何涉及玉玛果/果冻果/营养素/生物结晶的线
- 做法: 运输和储存都用果子 (1 小时), 到用的地方再加工成果冻 (4 分钟) / 玉玛果泥 (3 分钟) (G14); 主干走传送带、易腐品直塞或短带、不囤; 蓝箱勾"清除未请求物品"排变质物; 多余的烧进供热塔 (L22); 不要边建边开机 (G15)
- 为什么: 配方只有一种腐坏原料时, 产物直接继承它的腐坏进度 (facts spoilage.crafting.inherits-freshness ✅: 50% 的果泥做出 50% 的营养素); 营养素 5 分钟线性腐坏 (facts spoilage.nutrients.5-minutes-linear ✅); 机械臂"腐坏优先"只对从容器取货有效、对传送带无效 (G13, L21); 物流机器人送货不看新鲜度, 社区说先取箱子最右一格、旧货烂在缓冲箱 (L10); 有人靠机器人物流积压近百万变质物 (G15)
- 代价 / 不适用: "直塞"让生物室之间互相锁死 (一台停全停), 要配 production.md P-prod-19 的备用营养素组装机; 高品质物品保质期更长 (精良 ×1.3 … 传说 ×2.5), 升品后的句芒线可以放宽
- 关联: 决定 planets.md P-planet-13 (句芒最怕堵死); 决定 layout-styles.md P-style-07 (直塞流派)
- 流派: 直塞 / 短带
- 出处: G14 (wiki 果冻果 2026-09-17 + 腐坏机制 2026-10-15, 2); L22 (论坛 2026-03, 3); G15 (Reddit 摘要 2025-01 + 论坛 2024-12、2025-11, 3); G13 (论坛官方回复 2025-03-18, 2); L21 (wiki + 官方员工 2024-11, 2); L10 (论坛 2025-09、2026-08, 3); facts spoilage.* (✅)
- 状态: 腐坏继承和 5 分钟已核实; "最右一格先取"没人实测过
- 沙盘怎么比: A = 果子运到用处再榨, B = 果泥直接上带运 100 格; 比到达时的新鲜度和变质物量

### P-logi-06 祝融星用管道代替传送带主线: 熔融铁/铜走管道, 就地浇铸; 跨基地用液罐车厢
- 情况: 祝融星铸造厂区; 新地星进口方解石后也适用
- 做法: 铸造厂区只铺熔融铁、熔融铜两根管, 铸造厂就地浇铸铜缆、齿轮、钢材、管道、传送带, 不运板材 (V19); 跨基地用液罐车厢 (50000 单位 ≈ 7500 块板, 多于货运车厢 4000 块), 管道泵装卸快 (P4); 大型采矿机直接喂铸造厂, 不走矿带 (V23)

### P-logi-07 太空平台物流: 枢纽就是仓库、不能放箱子和机器人; 运原料不运成品; 推进剂只能船上现做
- 情况: 星球间物流和平台补给
- 做法: 平台上没有箱子和机器人, 枢纽 (59 格) + 接驳扩展仓 (+20 格) 就是全部仓库 (L24); 中间品比成品便宜发射 (V5); 2.1 起混装火箭 (小请求先装, 装不满补请求量最大的) 和"从任意来源进口"、平台互供 (changes-2.1 第 5 节); 2.1.13 起星系边缘也能平台互传 (SL11); 推进器燃料/氧化剂不能装桶, 快船也得自带化工厂, 只能向补给平台要碳、铁矿、冰 (SP5); 冷/热氟酮可以装桶运上平台 (A2), 量子处理器可以在平台做 (A5)
- 为什么: 火箭容量按重量 (1000kg) 不按格; 钷素星块堆叠 1、重 100kg, 一枚火箭只带 10 块 (L6) → 钷素船必须在船上做瓶, 不能运星块回地面 (ER7)
- 代价 / 不适用: 平台互传的中转 (船 → 停泊平台 → 另一艘船) 在 2.1 早期走不通, 2.1.12/2.1.13 改过, 要在 2.1.24 重测 (SP21, SP22); 平台离开前会等投放槽清空, 停在轨道不走先查垃圾 (changes-2.1 第 5 节); 角色上平台背包必须清空, 弹药能不能带有分歧 (S22 vs SP33)
- 关联: 火箭发射井可按物流网请求自动送货 (本机 orbital-logistics 提示) → 发射井要接物流网 (P-logi-02 的例外: 发射井是"请求方"); 星球可以向平台要物资但自己也在请求同种物资时不要
- 流派: 通用
- 出处: L24 (wiki 太空平台 2026-10-16 + FFF #449, 2); V5 (Reddit 摘要 2025-05, 3); SL11 (本机更新日志 2.1.10 ~ 2.1.24, 1); SP5 (B 站视频 2026-10-17, 4; 本机不能装桶, 1); A2、A5 (wiki 2026-10-20, 2; B 站视频 2026-09-23, 4); L6、ER7 (本机原型, 1; 论坛 2025, 3); SP21、SP22 (论坛 2026-06, 3, 可能过时); S22/SP33 (wiki + 论坛 2024-12 vs B 站游戏维基 2026-10-31, 2/3)
- 状态: 待核实
- 沙盘怎么比: A = 向平台送 500 铁板, B = 送 500 铁矿 + 船上电炉; 比火箭数; 另测"船 → 停泊平台 → 船"中转在 2.1.24 通不通

### P-logi-08 火车时刻表: 必去的站放主表, 加油和仓库放中断; 遥控过的车不会自己去加油
- 情况: 任何自动火车 (2.0 起有中断)
- 做法: 每次必去的站放主时刻表, 可跳过的 (加油、仓库) 放中断 (T24); 加油中断目标站要写等待条件 (如"静止 5 秒"), 条件写具体燃料 (煤矿 < 10) 而不是"任意燃料" (T22); 仓库中断加"货舱为空", 只让空车去仓库 (T25); 双头车用"任一机车燃料"不用"全部机车" (T22); 新车站先停用状态建好再启用 (T25)
- 为什么: 时刻表里只要有临时站, 火车就不检查中断 (官方: 有意的) → 被手动或脚本派了临时站的车不会触发加油中断 (T21); 中断只追加临时站、不替换主表、不检查下一站开没开 (L15); 不写等待条件 → 机械臂不给"不等"的车装燃料 → 无限循环 (T22); 混装燃料时"任意燃料"条件对木材成立而出发条件看煤 → 循环 (T22)
- 代价 / 不适用: 我们的 io-client 遥控火车 (临时站) 时要自己管燃料 (T21); "目的地已满"类中断有 0 ~ 1.5 秒延迟 (T26, 2.0.72 报告, 待测)
