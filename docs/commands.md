# 给模型的命令 (commands/)

模型只有一条命令行 `./fh` (派对的命令行, MIT, 见 NOTICE; 命令名不改, 因为它的参考手册和模型的习惯都叫它)。它把每条命令发到一个只属于这个角色的管道 (`FH_SOCKET`), 管道那头是我们的代理 (`broker.ts`), 代理决定:
- **读命令** (inventory / observe / inspect / status / nearest / stock / sleep 的条件…) → 问游戏外的模组宿主 (`game/offgame`): harness 的 Lua 原样答, 数据来自读内存; 内存读不到的 (流体、红绿线、物流网、别的玩家、地块) 宿主回头问注入客户端的只读查询。
- **账本命令** (sleep / tell / chat_ack) → 也在外面的模组里跑, 不碰游戏。
- **动作** (move_to / build / transfer / craft / mine / rotate / research / say / build_path / collect / refuel / feed / shoot) → 行动层 (`actions.ts`) 翻译成玩家操作: 走路 (`walk.ts` 自己寻路 + WASD)、放建筑和取放 (`body.ts`: 直接发玩家动作, 格子带物品 ID)、界面 (`gui.ts`: 手搓、研究、设配方)、键鼠时间线 (`timeline.ts`), 都经注入客户端的程序 (`game/client`) 发出去; 回复格式照模组。没翻译的动作明确拒绝, 什么都不发。
- **直接读游戏** (2026-11-09 起): `./fh call mcp --args '{"tool":"world_query","args":{...}}'` 把注入客户端的只读工具 (world_query / world_overview / ui_read / input_bindings / chat_read) 原样交给模型, 代理直接答 (`client-reads.ts`), 不过身体锁、不进行动层; 动作类工具和截图一律拒。回复超过 2.4 万字只回开头, 全文写进角色目录 `mcp-last.json`。上游 (factorio-mcp) 以后再加的读法, 模型当天就能用, 不用等我们逐项接。`./fh call belt_lanes` (传送带每条道上有什么) 是在它上面用批量相对读做的一条命令。两条的说明在 `own-help.ts` (`./fh help mcp` / `belt_lanes` 由包装答, 派对 harness 里没有这两条), 例子在沙盘里真跑过。
- **只读模式** (`--read-only`): 所有动作在代理就拒了。
- **协助模式** (别人的服务器): 建筑只动自己放的 (读 `last_user`), 别人的箱子最多拿一半, 用户点头的位置才能换; 模型自己开不了。

模型手里没有 RCON、没有 Lua: 管道只转 harness 请求, 管理操作 (生成角色、改时间、存档) 走沙盘的 RCON, 命令行连不到。

## 代码
| 文件 | 做什么 |
|---|---|
| `fh.ts` | `./fh` 的包装: 起停服务器的命令不给模型; `help 主题` 大的先回目录、按段看 (`ref-sections.ts`); `say` 加富文本标签 (`chattags.ts`: 星球、坐标 → gps、官方中文名加图标); 输出封顶 9000 字 (`output-cap.ts`); 回复后面附相关积累 (`hints.ts`: 放机器 / 查东西 / 报错时各一种, 有间隔, 压缩后重新给)。给程序读的 (`--format`、`FH_MAX_OUTPUT=0`) 不附不封 |
| `know.ts` | `./know 关键词`: 查全部积累 (`core/run/knowledge.ts` 读训练集: 思路 / 事实 / 要点 / 教训 / 资料, 官方中文名和内部名互查) |
| `cli/` | 派对的 `fh` 命令行 (编译好的 JS, 原样; 只放开 `--bot` 的名字规则): 发请求、`--wait` 轮询、输出格式、`help` 查手册、`sleep` / `wait` |
| `broker.ts` | 管道服务 + 路由 (沙盘混合模式 / 真服模式 / 只读), 起游戏外的模组宿主, 同一个 id 重发接到第一次的结果上 (命令行 5 秒没回就重发, 动作常要几秒), 回问注入客户端的只读查询, `where` / `probeStats` / `evalLua` / 管理员留言 (`operatorCall`) |
| `actions.ts` | 动作翻译: 够得着 (10 格 / 挖矿 2.7)、一条命令最多干 60 秒 (命令行等 90 秒)、批量动作先回做了多少、协助模式闸门、开枪 (按住开火键, 每 15 tick 看血量) |
| `body.ts` | 行动层 (包在注入客户端的程序外面): 放建筑 / 取放用直接发玩家动作 (格子带物品 ID + 品质 ID, 从读内存来; 空格填 0; 发完按读回补差额), 暂停时不发、别人同时操作要让出、开地图时退出远程视图 (`ensureBody`) |
| `walk.ts` | 寻路 (A*, 踩带子代价 0.25、机器缝、终点被占停最近空位) + WASD 长按 (每 10 tick 重按, 切窗口不停) |
| `gui.ts` | 界面: 开角色窗口、手搓、研究、设配方、设请求、贴蓝图 (都走界面点击 + 读回) |
| `query.ts` | 注入客户端的只读查询: 玩家、背包、研究、区域实体 (分页)、物流请求、配方 |
| `client-reads.ts` / `own-help.ts` | 模型直接用的只读工具 (`mcp`) 和看带子每道 (`belt_lanes`), 它们的 `./fh help` 说明 |
| `client-target.ts` / `io-types.ts` | 注入客户端的程序包成统一接口 (读 + 挂接 + 动作), 行动层继承它 |
| `timeline.ts` / `controls.ts` | 键鼠时间线 (长按一律重按) 和按键映射 (从游戏读, 不写死) |
| `drag-guard.ts` / `drag-guard.ps1` | 拖游戏窗口不卡游戏 (Windows 移动循环卡主线程) |
| `backend.ts` / `pipe-client.ts` | 走哪条路 (RCON + 模组 / 内存外挂) 和管道客户端 (开班那块用) |

## 规矩 (旧项目踩过的坑, 测试守着)
- 动作只报"已发出", 效果要读回来核对; 落地延迟不固定 (5~40 tick), 一律轮询读回, 不按固定 tick 等。
- 选中不注入 (注入过一次客户端自己的鼠标选中就失灵): 真鼠标悬停让客户端自己发选中, 再注入开窗口。
- 手上空着按清手键 = 吸管 (把指着的东西吸到手上): 先看手上有东西才按。
- `build` 按"手上加背包少没少"判断放没放下 (那格本来就有时不算成功); 走得过去不等于放得下 (干跑用放建筑的规则)。
- 一条命令要在 90 秒内答: 不带 `walk: true` 最多走 64 格, `move_to` 一次最多 400 格, 批量干 60 秒先回做了多少。
- 动作回复时手上的东西要回背包才回 (大世界 / 联机延迟下读回不干净)。
- 协助模式闸门在行动层 (RCON 那条路没有, 只靠简报)。

## 证据 (游戏 2.1.24)
旧项目同一套代码: 动作核对 41/41 ~ 46/46 (沙盘和联机服务器存档副本); 联机服务器上只读进世界、放一个石炉再拆回、聊天 3 句, 没被踢没不同步, `console_command_used = false`; 本机新图不装模组不碰 RCON 真拿到 Steam 成就 (打掉虫巢)。
新项目回归 (2026-11-07, 新图): `test/sandbox/actions.test.ts` 38/38 —— 读走外面; 走 8 格差 0.26 格; 放炉子 / 木箱 / 组装机带配方 / 机械臂朝向 / 批量 3 根杆; 取放数量全对 (煤 7、矿 10、铁板 25 放 10 取、弹匣 10 进炮塔); 手搓 6 齿轮; 铺 8 格带子重跑不重复; collect / refuel / feed; 协助模式 4 条闸门; 干跑报挡着; 挖 3 个矿; research 排 / 查 / 只取消那一项; 建筑压矿上取放拆; 捡尸体 3 炮塔 77 铜线全回; 打虫巢和虫子; 地块 (水、抽水机); 逆带子走路、终点被占; 换地表 (gleba) 读数跟着走; 注入 Lua 的流体 / 锅炉状态 / 红绿线 / 物流网 / 第二个玩家全对真值, 服务器没有不同步。

**2026-11-09 (默认路线的积累工具, `test/sandbox/actions.test.ts` "积累")**: `./calc` 出配比表、`./plan 红瓶 10` 出带 `./bp build` 的方案、`./bp list` 列库、`./bp build 1` (16 座石炉冶炼列 114 件) 4 条命令 167 秒放完, 件数对真值 (石炉 16、机械臂 32、带子 54、电线杆 12)。查出并修了: ① 接着放时预检算缺料没减掉已经放下的, 第 3 条命令误报缺机械臂停住 (`buildCheck` 减 existing); ② 一条命令只放 11~14 件 (每件重新开背包拿、放歪了清空手去转实体): 批量放按物品 / 方向排 (`buildOrder`), 带子和机械臂放歪了转手上方向原地再放, 直线段带子拖着放 (`dragRun`), 一条命令放到 21~62 件。水管直线段也拖 (15 件 26.1 → 13.9 秒, 连成一个流体系统)。
