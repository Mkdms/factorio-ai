# 沙盘完整链路: 大脑从空地玩到自动化红瓶

起因和依据: factorio-ai-party 证明大模型 + 好 harness 能玩到太空时代后期 ([research/factorio-harness.md](research/factorio-harness.md))。M0~M4 一直在造身体和接口, 大脑还没真正玩过 —— 这是项目最大的未知, 先把它量出来。

## 目标和完成标准
- 新地图 (新地星, 跳过开场), 大脑 (Claude) 只靠"像玩家一样"的动作 (够得着、只用背包里的东西、真实时间), 从空手开局玩到**组装机做自动化科技包（红瓶）、实验室吃机器做的红瓶连续研究 ≥ 10 游戏分钟** (不靠手搓供瓶)。
- 每轮记录: 游戏时间、真实时间、回合数、token (从会话日志算)、死亡次数、空闲占比、失败动作数和原因前 10。达不到也算有结果: 卡在哪就是 harness 下一步要补的。

## 结构
```
大脑 (Claude Code 会话) ─Bash─► fp 命令行 ─RCON─► 沙盘服务器 ─► 角色
                                              ├ io-lab: 布场、真值 (上帝模式, 只给测试用)
                                              └ agent-harness: 玩家规则下的动作 (搬自 factorio-harness)
观看窗口跟着角色 (用户能看)
```

## 步骤
1. **搬底子**: 上游 factorio-harness 的模组搬进 `mods/agent-harness/` (NOTICE 署名, MIT), 改 2.1 断点 (约 15 处: neighbours、fluidbox、recipe.category) 和 info.json; 从分支版挑失败原因的写法 (`bots.lua` 服务器直接造角色, 留到以后批量跑再搬; 回合模式不要, 见下)。先实测 2.1.24 能不能加载。
2. **动作测试**: 红瓶链路要用的动作每个写一条沙盘真值测试 (RCON 读真值, 进 `test:sandbox`): observe、move_to、mine、craft、build、transfer (加燃料 / 取产物)、rotate、configure (设配方)、research、belt_route + place_ghosts + construct、电线杆路线。

4. **大脑**: 简报短 (身份、目标、规则: 只准用 fp; 怎么查帮助和我们的知识库), 笔记 `notes.md` 固定格式; 交互式 Claude Code 会话, 只开 Bash / Read / Edit; 监工: 空闲时提醒继续; 设截止时间。第一轮不做开局引擎, 先量大脑自己玩的回合和 token, 再决定哪些步骤值得交给确定性代码。

## 沙盘模组和联机服务器的关系
- agent-harness 模组**只装在本机沙盘服务器** (和 io-lab 一样), 联机服务器上什么都不装。
- 大脑只认 `fp` 这一套命令; 背后两种实现: 沙盘 = 模组经 RCON 执行; 联机 = io-client 在自己的客户端里把命令变成普通玩家输入 (factorio-harness 的客户端桥在 2.0.77 上核实过走路、采矿、建造、手搓不掉同步)。
- 为什么不能只装在本地: 联机时服务器和每个客户端各算同一份模拟, 只同步玩家输入 → 模组必须两边一样, 服务器没有的模组客户端连不进去; 硬塞进本地改状态会掉同步被踢。能放在本地的是它的**逻辑** (算路、检查、报错、压缩输出、队列), 最后只发普通玩家输入 = io-client。
- 两种执行方式能不能一起用: 沙盘里两种都能用 (大脑第一轮用模组版; 走路核实用本地版, 服务器不装模组), 联机只能用本地版; 同一个角色同时只用一种。模组版的用处: ① 不等 io-client 先把大脑量出来; ② 当本地版的标准答案 (同一套 `play:check` 两边各跑); ③ 按大脑的调用分布定本地版先做什么 (第一轮: transfer 79、move_to 75、scan 61…); ④ 快速、可重复、能批量地练和评测。差距: 模组版有些动作比本地版快得多 (例: 放 37 个物品, 本地点界面约 0.2 秒一个) → 本地版每做好一个动作, 就在沙盘里切到本地版跑同一轮, 量出差距。
- 不需要 RCON、不需要作弊: 联机时能改世界的只有 ① 所有人都装了的模组 Lua 和 ② 玩家输入。agent-harness 守的是真人规则, 但它用 Lua 直接改 (设走路状态、调采矿函数、塞物品栏), 所以只能在大家都装了它的地方用; RCON 只是沙盘里递话的通道。我们本地能读 (factorio-mcp 只读查询)、能算 (算路、检查)、能发玩家输入 → **"agent-harness 在本地" = 每个动作改写成"本地算 + 发玩家输入", 命令和报错不变** = io-client:

  | 动作 | 沙盘模组怎么做 | io-client 怎么做 | 状态 |
  |---|---|---|---|
  | 走到某点 | Lua 设走路状态 + 游戏寻路 | 本地读障碍、算路, 按方向键 | ✅ 2026-11-02 4/4 |
  | 采矿 | Lua 计时调采矿函数 | 鼠标指着矿按住采矿键 | 客户端桥在 2.0 核实过, 待做 |
  | 建造 | Lua 从光标建 | 物品拿到光标, 点地面 | 待做 (T7) |
  | 放取物品 | Lua 塞物品栏 | 点界面格子 (✅ T8, 慢) → 按格转移输入 | 部分 |
  | 设配方 / 请求 | Lua 设 | 点界面 | ✅ T9 |
  | 手搓、研究 | Lua 调 | 界面或输入 | 待做 |
- 每个 Lua 改动都有对应的玩家输入动作: 设走路状态 → "开始走 / 停止走"输入; 游戏寻路 → 本地算路; 计时调采矿函数 → 选中矿发"开始采矿"; 从光标建 → "建造"输入; 塞物品栏 → "转移物品"类输入; 设配方 / 手搓 / 研究 → 对应输入或点界面; 够不够得着、能不能放 → 客户端里用游戏自己的只读判断函数 (factorio-mcp 只读查询)。发法两种: 按键鼠标 (factorio-mcp 现成, 稳但慢) / 直接发游戏输入动作 (factorio-mcp 发聊天就是, 2.1.24 约 330 种, 快而准, 数据格式逐个在沙盘核实)。**io-client = harness 的判断逻辑搬到本地 + 用输入动作执行**, 命令和报错和沙盘版一样。
- 规矩: 每个给大脑的动作都标 **联机能不能做** (能 / 待核实 / 不能); 第一轮只用联机也做得到的; 服务器端才能做的 (例: 调游戏寻路) 要么在客户端用只读计算重做, 要么不给大脑。到 M4 逐个核实。

1. 修坏的: 上面几条先核一遍, `./bp build` 要一次成; 放不下时回复直接给能放下的坐标。
