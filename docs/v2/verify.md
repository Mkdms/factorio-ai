# M2 核实: 把检索来的说法放进沙盘实测

> 2026-10-31 起。经验主要靠全网检索 (`docs/research/players/`, 约 370 条说法 + 2.1 变化 44 条); 影响设计的说法要在沙盘里实测, 通过的才进知识库 [`knowledge/facts.md`](../knowledge/facts.md), 才能当设计依据。

## 怎么用
```bash
npm run verify                    # 先无窗口干跑一遍 (实验自己出错 / 摆错 / 靠自动补杆就停), 过了再开窗口正式跑并写进 knowledge/facts.json 和 facts.md
npm run verify -- --only heating  # 只跑编号里带 heating 的
npm run verify -- --only X --dry  # 只干跑 (无窗口、不写知识库)
npm run test:sandbox              # 回归: 全部实验重跑一遍 (不开窗口、不改知识库), 结果和记录不一样就报错; 104 个实验, 超时 60 分钟
```

## 加一个实验
1. 在 `experiments/` 下写一个文件, 导出 `Experiment` (见 `src/verify/types.ts`): 编号、主题、说法 (用官方中文名)、关联的检索编号和第一版教训、出处 (带可信度)、`run(ctx)`。
2. `run` 里用 `ctx.lua(代码)` 在本实验独占的 40×40 区域 (中心 `ctx.x, ctx.y`) 摆东西, `ctx.ticks(n)` 跑时间, 读数后返回 `verified` / `refuted` / `inconclusive` 和带实测数字的中文结论; 物品名用 `ctx.zh(内部名)` 翻成官方中文名。
3. 在 `experiments/index.ts` 登记, 跑 `npm run verify`。

## 写实验的规矩 (从踩的坑来)
- **不手敲坐标**: 放东西用 `lab.place`, 挨着机器的格子用 `lab.slots`, 流体接口用 `lab.connections`, 供电用 `ctx.power()`; 测量前 `ctx.powered()`; 机器实际位置以建出来的 `entity.position` 为准 (3×3 的会被挪半格)。
- **读不到数就是没结论**, 不能当成 0 或"推翻" (第一批有两次读数代码写错, 框架照实记成没结论)。
- **要有对照组**: 例如测"绿箱先于黄箱", 先确认绿箱在这个设置下确实能供货, 否则结论没意义。
- **随机的要够样本**, 按二项分布给误差范围 (铜细菌 718 次, 允许 4 个标准差)。
- 找回实体用名字 + 位置 (`find_entity`), 不用 `game.get_entity_by_unit_number` (2.1.24 实测: 供热塔、箱子、生物室都查不到)。
- 实验只证明它测的那个场景; 结论写清楚条件 (例如"蓝箱勾选了从缓存箱请求")。
- **防线 (2026-11-02, `test/sandbox/guards.test.ts` 有测试)**: 开测前机器状态里有缺燃料 / 没电 / 缺流体 / 没配方 / 冻住的就不测量 (缺原料、输出满是正常过渡状态, 只记录), 故意的写 `allowStatus`; 出结论前对所有实验查布局; 实验前后对比全局状态 (场地外新建、配方变化, 记在 `rec.leaks`)。先摆装置再 `ctx.power()` (先铺电会压到装置)。
- **写说法前先查知识库**: grep `knowledge/facts.md`、`knowledge/patterns/`、`docs/research/players/` 同主题的条目, 写进 refs (2026-11-02: 岩浆支架那条, 检索 T8 早写了"不能", 我没查就推了相反的说法)。
- **测量前一律调 `ctx.powered()`** (不接电的实验也调: 它不补杆, 但查布局、记开测前机器状态); 往机器 / 箱子里塞东西用 `lab.insert` (塞不全就报错, lab.md #45)。

## 游戏外设计 → 精准导入
`src/blueprint/design.ts`: `encodeAbsolute(设计清单)` 把世界坐标的设计编成**绝对吸附**蓝图 (格子左上 = 蓝图 (0,0), 实体坐标原样), 放的时候只能落在设计的那一格; `diffPlacements(设计, 实际)` 放完逐格核对名字、位置、方向。沙盘里用 `place_blueprint`; 联机身体 (M4 io-client) 要走玩家操作: 导入用"拖文件进游戏窗口" (2.0.25 起) 或导入窗口的"粘贴"按钮 (1.1.105 起), 不受 1024 字符限制 (第一版卡在这里); 放下后再逐格核对。朋友整个新地星基地 (43125 件) 在沙盘里一次放下 42928/42928。

## 学别人的蓝图

说法照 wiki 原文 (Belt transport system 2026-01-14 版、Splitter 2026-04-11 版), 地下带距离对照本机原型。
| 说法 | 结果 |
|---|---|
| 分流器 1:1 均分; 一个出口堵满时全走另一个 (TT6) | ✅ 一条满带 (15/秒) 进: 北 7.50 / 南 7.50; 堵死南边收料箱后 北 15.00 / 南 0 |
| 输出优先: 先全给指定那边, 满了才给另一边 | ✅ 朝东设"左" = 行进方向左手边 = 北: 北 15.00 / 南 0; 堵北后 北 0 / 南 15.00 |

| 过滤: 设定的物品全走指定出口, 其他全走另一边 | ✅ 都通: 北只有铜板 15、南只有铁板 15; 堵北: 铜板不改走南 (南的铜板 0, 铁板照走 15); 堵南: 铁板不改走北 → **过滤是死的, 不会溢出到另一边**, 那边堵了这种物品就停 |
| 分流器保持车道 | ✅ 只有右道有货的带子进: 两个出口都只有右道 (各 24 件, 左道 0) |
| 分流器速度 = 同级带速, 不是瓶颈 | ✅ 两条满带进、两条出: 基础 / 高速 / 极速 / 超速 合计每秒 30.00 / 60.00 / 90.00 / 120.00 |
