# 别人的教训 (不是我们犯的, 但一样要防)

## 朋友的 agent
他的 agent (跑在 GPT 上) 用他的 factorio-mcp 截图:
1. **放着成熟库不用, 自己写**: 返回的 PNG 是 agent 自己在 Kotlin 里拼的, 问它为什么不用 libpng, 它说忘了。
2. **工具输出没有上限**: 截图工具没有尺寸参数, 每次截一张 20MB 的图; 一晚上跑了十几 GB; 图要经他的代理发到 OpenAI 服务器, 把代理流量用光了。他事后加了尺寸参数: "反正是像素游戏, 800×600 就够了"。

## 我们的规矩 (写进 CLAUDE.md 和架构 3.4)
| 规矩 | 怎么落实 |
|---|---|
| 优先用成熟库, 自己写只限于没有库的部分 | 图片: sharp / pngjs; 压缩: zlib; 数据库: node:sqlite; MCP: 官方 SDK; RCON 这种协议小到没有可靠的库才自己写, 但要有对照测试 (我们的 RCON 有假服务器测试) |
| 每个工具的输出都有上限, 默认就是小的 | 图片默认最长边 ≤ 800、≤ 300KB, 要大图必须显式传参数并说明理由; 文本默认分页 (`共 N 条, 显示前 M 条`), 大数据先压缩 (io-lab 回复 >4KB 自动压缩; 超过 8MB 直接拒绝, 提示分页) |
| 发给模型的东西记账 | 每次调用记字节数和 token, 每个任务有预算, 超了报警; 模型默认拿缩略图, 全分辨率只在明确要求时给 |
| 像素游戏不需要高清 | 视觉核对用 800×600 以内的截图; 结构化读取 (实体、状态) 优先于截图 (架构里的 vision MCP "只在结构化读取看不到时用") |
| 开发时也一样 | 子代理和实验的输出都截断; 读大文件用分页 |
