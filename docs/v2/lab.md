# 沙盘身体 io-lab (M1)

> 2026-10-31 完成, 本机 Factorio 2.1.24 + 太空时代实测。只用于本机沙盘, 从不连别人的服务器。

## 一条命令
```bash
cp .env.example .env            # 填 FACTORIO_DIR
npm run lab:demo -- --minutes 10 --instances 2
```
并行起 2 个无界面服务器 → 各建一张新图 (含太空时代) → 放演示蓝图 → 加速跑游戏内 10 分钟 → 读产量 → 比较两边结果。本机实测: 每个实例全程约 15 秒, 两边产量逐项相同, 和计算一致 (采矿机 0.5 个/秒 × 600 秒 = 铁矿 300, 齿轮 149)。

**可视化 (默认开)**: 本机 `.env` 里 `LAB_VIEW=1` 时, 每次做沙盘实验都会另开一个游戏窗口连进去, 聊天框里有中文说明; 实验做完窗口再留 60 秒 (`LAB_VIEW_LINGER`) 才关; 窗口在时速度上限 20 倍 (`LAB_VIEW_MAX_SPEED`), 太快窗口跟不上。回归测试不开窗口。

**观看模式** (想长时间看): `npm run lab:watch` —— 沙盘按正常速度跑, 另开一个游戏窗口 (单独的配置和数据目录 `lab-data/clients/viewer/`, 不碰你自己的游戏) 自动连进去, 在聊天框里用中文播报每一步和每分钟的产量; 你是管理员, 可以 `/c game.speed = 10` 加速; 关掉窗口, 沙盘自动关闭。

其他命令: `npm test` (单元测试, 不开游戏)、`npm run test:sandbox` (沙盘集成测试, 约 11 秒)、`npm run lab:dump` (导出原型数据和中英文名称)。

## 组成
| 文件 | 做什么 |
|---|---|
| `mods/io-lab/` | 正式模组 (不在运行时注入脚本): 一个 remote 接口 `io-lab.rpc`, 事件统一分发, `storage` 只放数据, UDP 快速通道 |
| `src/lab/instance.ts` | 一个实例 = 单独的数据目录 (`lab-data/instances/<名字>/`: config.ini、mods、saves、日志) + 自己的端口和随机 RCON 密码; 建图、起服、停服、导出原型数据 |
| `src/lab/rcon.ts` | RCON 客户端: 回复按 id 认领、启动中/存档中按退避重试、超时断开重连 (只读命令自动重试一次)、存活检测 (`heartbeat`, 连续 2 次失败发 `dead`) |
| `src/lab/udp.ts` | UDP 通道 (`--enable-lua-udp`), 大回复分段 |
| `src/lab/blueprint.ts` | 蓝图字符串编解码、`helpers.encode_string` 解码 |
| `src/lab/viewer.ts`、`watch.ts` | 观看用的游戏窗口 (单独配置, 模组和服务器一致) 和观看模式 |
| `src/lab/demo.ts`、`cli.ts` | 演示和命令行 |

## io-lab 的方法
都经 `LabInstance.rpc(方法, 参数, {via: "rcon" | "udp"})` 调用。回复一律是 `{ok, data | error, tick}`; 收到的不是这个格式就报"没读到", 不当成读到空。回复超过 4KB 自动用 `helpers.encode_string` 压缩。
| 方法 | 参数 | 返回 |
|---|---|---|
| `ping` | — | tick、模组版本、速度、是否暂停、UDP 是否开 |
| `exec` | `code` (Lua, 用 `...` 取 `args`) | 代码的返回值 (要能转 JSON) |
| `time` | `speed`、`paused`、`run_ticks` (暂停状态下精确跑 N 个 tick) | 同 ping |
| `prepare_area` | `area`、`tile`、`resource {name, amount, area}`、`no_enemies` | 清掉的实体数、铺的地砖和矿 |
| `place_blueprint` | `string`、`position` (蓝图原点落点)、`anchor:"center"` 用游戏原来的中心对位 | 幽灵数、建成数、失败清单、实际偏移 |
| `inspect` | `area` | 实体计数、状态计数、容器里的物品 |
| `score` | `force` | 自带 production-score、按"产出 - 消耗"全算的价值、每种物品的产出和消耗、价格 |
| `audit` | `area`、`boxes` (要列出流体接口的实体位置)、`shapes` (带弯道和没下游的全部位置)、`cap` | 引擎级核对清单 (每张 `{n, items}`): 没电的 (带 `network` 是否在电网里)、传送带没上游 / 没下游 / 形状统计 / 地下带没配对、流体接口接上几个 / 空着哪些 / 一个口都没接的、铁轨端点接上几个 / 尽头、信号和车站有没有连到轨 |
| `power_networks` | `area` | 给区域里每张电网接一个电力接口 (试放别人的基地时没燃料, 先把电供上) |
| `power_fix` | `targets` (没电实体的位置) | 每个旁边按供电半径放配电站 + 电力接口; `ctx.powered()` 发现没电时自动调 |
| `say` | `text` | 在游戏聊天框里说话 (观看模式播报) |
| `viewer` | `position`、`zoom` | 给已连进来的玩家开管理员、不受伤、移到实验区; 返回玩家名单 |
| `save` | `name` | 存到实例的 saves 目录 (回档 = 用这个存档重新 `start`) |
