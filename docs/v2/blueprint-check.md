# 蓝图静态检查器 (布局 MCP 的第一道关)

> 2026-11-01。实验里电线杆盖漏、机器被挪半格、雷达没电: 规则全在原型数据里, 错在人手摆放没走代码。所以基地蓝图要过三道关: **生成器按数据算位置 → 静态检查器 → 沙盘引擎核对**。这里是第二道。

## 用法
```bash
npm run bp -- check <蓝图文件>     # 不开游戏, 43125 件的基地几秒钟; 有错误退出码 1
```
规则不手写: `src/blueprint/rules.ts` 从本机导出的原型数据 (`lab-data/prototypes/<版本>/data-raw-dump.json`) 提取碰撞盒、供电范围、连线距离、地下带/地下管道最大距离、机械臂取放向量、流体接口 (位置 + 朝向 + 进/出)、配方用几种流体。游戏更新后重新导出就是新规则。

## 查什么 (`src/blueprint/check.ts`)
| 检查 | 规则来源 | 级别 |
|---|---|---|
| 重叠: 两个实体占同一格 (按各自朝向旋转后的碰撞盒, 可以不对称; 铁轨之间除外) | collision_box | 错误 |
| 供电覆盖: 每个用电建筑的碰撞盒要碰到某根杆子的供电方块 | supply_area_distance | 错误 |
| 电网连通: 按蓝图里的铜线 (没有铜线时按连线距离) 分连通分量; 有发电设备但不同网 | maximum_wire_distance | 警告 / 提示 |
| 传送带迎头相对 | 朝向 | 错误 |
| 地下传送带入口在最大距离内没有同向出口 | max_distance (黄 5 / 红 7 / 蓝 9 / 绿 11) | 错误 |
| 地下管道在 10 格内没有对着它的另一头 | max_underground_distance | 警告 (单根当封口是常见用法) |
| 流体口对面没接管: 机器的进/出口 (按配方的流体数量决定哪些口有效: 化工厂 2 个进口做硫酸只用第 1 个) | fluid_boxes + 配方 | 警告; 穿过式 (蒸汽机、锅炉排尾) 提示 |
| 机械臂取货格 / 放货格是空地 (铁轨格算有车厢) | pickup_position / insert_position + 朝向 | 警告 |
| 车站: 铁轨要在车站朝向的左手边 2 格 (= 列车行进方向右侧是车站) | 沙盘实测 | 错误 |
| **传送带连续性** (`check-belts.ts`, 2026-11-01 加): 带子顶着分流器的侧面 / 地下带的罩子 (货过不去) | 分流器只从背后接; 地下带入口背后和侧面进、出口只接侧面 | 警告 |
| 侧向汇入 / 弯道分类 (有上游或两侧都汇 = 直带被侧汇, 只一侧来、没上游 = 弯道); 尽头顶建筑 / 尽头空地的数量 | 沙盘核实 belt.sideload (第四批) | 提示 |
| 整段带子 (≥3 件) 没有来源 (没机械臂放货、没采矿机出料、没装卸机) / 没有去处 (没机械臂取货) | 机械臂取放向量、采矿机 vector_to_place_result | 警告 / 提示 |
| **管网连通和混管** (`check-fluids.ts`): 每个流体箱一个节点, 接口互相对着 (连接类别相同) 或地下管道配对就连通; 同一张网两种流体 = 混管 | 流体箱 filter (锅炉 water/steam、蒸汽机 steam、聚变) + 配方 (进口箱按流体原料顺序、出口箱按流体产物顺序) | 错误 |
| 管网只有进口、没有出液的机器: 管子留了口 → 外部供液 (提示); 没留口 → 没来源 (警告); 只有出液没用液 → 会憋满 (提示) | — | 警告 / 提示 |
| **铁轨** (`check-rails.ts`): 每种铁轨每个朝向的两端 (位置 + 出口方向) 和落点奇偶来自沙盘引擎导出的 `rail-geometry.json` (`npm run lab:dump`); 两端位置相同、方向相反 = 相接 | 引擎 `get_rail_end().location` (lab.md #22) | 不在网格 = 错误; 碰头但方向不对 = 警告; 分成多张网 = 警告; 尽头数 = 提示 |
| 信号: (相对铁轨的偏移, 朝向) 必须在引擎认可的表里 (= 贴着轨、面朝来车 = 在行进方向右侧) | 引擎 `can_place_entity{build_check_type = manual}` 扫出来的表 (lab.md #23) | 错误 |

朝向约定 (2.0 蓝图, 16 向): 北 0、东 4、南 8、西 12; 向量按实体朝向顺时针旋转。信号的朝向 = 它面对的方向 (迎着来车), 和列车行进方向相反: 东西直轨南侧的信号朝西, 管东行的车。

## 验证 (2026-11-01)
- 单元测试 `test/blueprint-check.test.ts`: 好样本 (演示蓝图) 0 错误 0 警告; 坏样本每条规则各一对 (该抓的抓住、擦边的放过): 杆子 4 格 vs 3 格、地下带 6 格 vs 5 格、地下管道 11 格 vs 10 格、机械臂对空地、车站朝向、重叠 (含抽取泵的不对称盒子)、化工厂流体口。
- 朋友的新地星基地 (43125 件): **错误 6、警告 31、提示 89**。6 个错误拿沙盘引擎逐个核对, **全部属实**: 1 座激光炮塔不在任何电网里 (`electric_network_id` 为空, 状态 60 没电, 周围 50 多座都在网里), 5 个基础地下传送带入口 `underground_belt_neighbour` 为空 (孤儿入口, 死头)。警告里"电线杆分成 2 张网"就是他给燃料机械臂单挂的那张小太阳能网 (抓对了)。
- 误报修过的: 抽取泵碰撞盒不对称 (往水里多伸一格) 曾被报成和管道重叠; 斜向直轨曾被报成不在网格上; 配方不用流体的机器曾报 961 条流体口。

## 第三道关: `bp try` 的标准报告 (2026-11-01 晚)
```bash
npm run bp -- try <蓝图文件> [--index N] [--seconds 20]
```
顺序: 静态检查 → 建图、铺场地 (两种落点的并集, lab.md #25) → 放蓝图 (按顺序第 1 件做参照, 反推不出偏移就报错) → 给每张电网接电力接口 (`power_networks`) → 跑几秒 → 引擎读数 (`audit`) → **静态 vs 引擎逐类对数**, 弯道和"没有下游"还逐个位置对。

朋友的新地星基地 (43125 件, 42928/42928 建成) 对数结果:
| 类别 | 静态 | 引擎 | |
|---|---|---|---|
| 地下传送带没配对 (入口 + 出口) | 25 | 25 | ✅ (原来只查入口, 5 个; 引擎两头都算) |
| 传送带弯道 | 1409 | 1409 | ✅ 位置逐个一致 (`belt_shape` left 658 + right 751) |
| 传送带没有下游 (尽头 + 顶建筑 + 顶不接的面 + 迎头) | 174 | 174 | ✅ 位置逐个一致 (`belt_neighbours.outputs` 为空; 要按件数算, 分流器两格算一件) |
| 铁轨尽头 (端点数) | 16 | 16 | ✅ |
| 信号位置不合法 | 3 | 3 | ✅ 同一 3 个 (y=157.5 那排北侧 11 个信号里 3 个朝西, 其余朝东; 引擎状态 `not_connected_to_rail`) → 朋友基地的真错 |
| 车站没接轨 | 0 | 0 | ✅ |
| 不在任何电网里的用电建筑 | 1 | 1 | ✅ 同一座激光炮塔 (沙盘刚建好时炮塔充能、机器人平台充电会短暂 low_power 239 件, 所以只比"不在电网里"; 蓄电器 / 太阳能是发电侧, 不算) |

7 类全部对上 (2026-11-01 第 9 次核对)。

做这份报告踩的坑 (都在 lab.md #25~#30): 蓝图按外框中心对位、参照件落在场地外反推失败 (6 次核对才发现坐标差了 (-56,-190))、Lua 清单带计数字段序列化成对象、Bash heredoc 吞反斜杠。

### 混管规则的修正 (引擎教的)
第一版把每个流体箱当节点, 朋友基地报了 3 处混管; 沙盘里化工厂 (做硫酸, 只用水) 的 1 个进口箱**两个口都"接上"** (东口贴着轻油管, 西口接水), 游戏里照常工作: 进口箱有过滤, 只拉自己要的, 不会把两边的管网并起来。所以: 端点箱 (只进 / 只出) 按"口"接到管段, 不并网; 混管 = 一张管段网里有两种**出液**或两种 filter (锅炉 water / steam, 蒸汽机 steam); 进口接到别的流体 → 警告"接错流体"。另外: 2.0 蓝图的 `mirror` 把流体口左右对调 (朋友基地 82 件带 mirror, 不处理会误报 2 处混管); 垂直方向的地下管道可以互相穿过, 只有同轴背对的才挡。改完朋友基地: 混管 0、接错 0、95 张管网、63 个进口靠外部供液。

## 覆盖检查 (`check-coverage.ts`, 2026-11-01 深夜)
范围全从原型读; 涉及的游戏规则都在沙盘核实过 (物流 25、建设 55、范围不重叠 = 两张网、边界刚好相接 = 一张网, 见 knowledge/facts.md)。
| 检查 | 级别 |
|---|---|
| 物流箱 (红/黄/绿/紫/蓝箱) 不在任何机器人指令平台的物流范围里 (按实体中心, 半边长 25) | 警告; 蓝图里没有平台时只提示 |
| 机器人网分几张: 物流范围重叠或边界相接就连成一张 | 提示 |
| 炮塔不在任何平台的建设范围里 (半边长 55, 坏了没机器人修); 墙 / 闸门不在建设范围里的数量 | 警告 / 提示 |
| 墙外 2 格不在任何炮塔射程里 (重炮不算; 有最小射程的按最小射程排除): 机枪 18、激光 24、火焰 30 (最小 6)、火箭 36 (最小 15)、磁轨 40 (最小 3.5) | 警告 (墙外 2 格是设计取舍, 不是游戏规则: 来拆墙的虫站在墙外) |
| 吃弹药的炮塔没有机械臂往里放 | 提示 (可能靠机器人或手补) |

朋友的新地星基地: 238 个机器人指令平台一张网 (按 50 格间距铺的, 边界相接; 原先按"相接不算"报成 111 张, 沙盘核实后改); 45 / 4634 段墙没有炮塔护着、4 座机枪炮塔在建设范围外、45 座机枪炮塔都没有补弹臂。错误数现在是 29 (地下带两头都查后 25 + 信号 3 + 激光炮塔 1, 和上面引擎对数表一致; 表上方"错误 6"是改之前的数)。

## 区段长度 vs 标准列车 (`check-blocks.ts`, 2026-11-02)
铁轨按端点连成图, 每个信号落在它所贴铁轨离它最近的端点 (= 区段分界), 没被切开的铁轨并成区段, 长度按两端点直线距离累加 (弯道略算短)。只查**普通信号后面、出口也有信号**的区段 (列车会在里面停下等), 短于标准列车就警告 (trains.md T2); 联锁信号后面的路口区段不查。标准列车长度是**临时值 4 节 (1-2-1, 约 28 格)**, 等定标准列车再改。另出一行统计 (多少信号找到接头、查了几个区段、最短多长), 看检查有没有真的在查。单元测试有两个方向的样本。
朋友基地: 99 个信号 96 个找到接头 (没找到的 3 个就是那 3 个朝西的错信号), 查了 64 个区段, 最短约 36 格 → 4 节列车不报; 他的列车如果是 2-4 (约 42 格) 最短的几个会放不下 → 可以问他列车多长。
