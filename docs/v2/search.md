# 按指标搜索 (M3)

> 2026-11-02 起。路线图 M3 "layout 的生成器还要继续"; 数据集下一步第 4 条 "搜索不只穷举: 按指标往好的方向改参数 (先爬山)"。
> 搜索只给候选和实测数字, 用哪个由设计师定 (架构第 2b 节)。

## 用法
```bash
npm run search -- --recipe iron-gear-wheel --target 600                       # 每分钟 600 个铁齿轮
npm run search -- --recipe inserter --target 120 --allow machine=assembling-machine-1,assembling-machine-2 --allow inserter=inserter,fast-inserter
npm run search -- --recipe electronic-circuit --target 300 --fix layout=double --start '{"inserter":"fast-inserter"}'
```
- `--allow 参数=值,值`: 只在这些取值里找 (**科技上限**: 没研究的机器 / 机械臂 / 带子不让用); `--fix 参数=值`: 固定不动。
- `--research late`: 全部科技研究完再测 (默认 none = 只解锁配方)。
- `--iters` 最多几轮 (默认 12); `--warm` / `--seconds` 喂料实测的预热和测量秒数 (默认 60 / 120, 游戏内); `--view` 开观看窗口 (默认不开: 批量测量, 窗口在时速度上限 20 倍)。
- 输出 (都在本机 `lab-data/search/`, 不进仓库): 每轮走到哪、实测过的前 8 名表、最好的蓝图 `<名字>.best.txt` (可以 `npm run bp -- link` 出预览链接、`bp render` 出图)、全过程 `<名字>.json`; 实测结果缓存在 `<名字>.cache.json`, 重跑不重测。

## 怎么搜 (`src/search/`, 纯函数有单元测试 `test/search.test.ts`)
1. **积木**: 组装机排生成器 `tools/generators/assembler_row.py` (见 [blueprint-dataset.md](blueprint-dataset.md) "自己生成"), 参数: 机器 (组装机 1/2/3 型)、进料臂 (电力 / 高速 / 集装机械臂, 远带固定用加长机械臂)、每台每条带几个进料臂 (1~3)、每台几个出料臂 (1~3)、带子 (4 档)、单排 / 双排、每排台数 (1~40)。一行放不下的组合生成器直接判不合法 (不进沙盘)。
2. **起点**: 计算器 (`src/calc`) 算满速要几台; 机械臂和带子从允许的最低档开始, 让搜索自己往上加。
3. **邻居**: 每个参数各改一格 (档位高一档或低一档; 台数 ±1 和 ±四分之一); 加两种**联动邻居**: 换机器档时按机器速度比例同步调台数, 单排换双排时每排台数减半 (双排换单排翻倍)。没有联动时第一次搜索停在 组装机2型 7 台 —— "换 3 型同时减到 5 台"要同时改两个参数, 一次只改一个走不到。
4. **实测**: 邻居一次生成一本书, 逐张进沙盘做喂料实测 (和数据集第三层同一套: 自动上料、收料、预热后分两半测)。
5. **打分** (按位比较): 先看达没达标 (实测 ≥ 目标 × 98%, 且趋势 ≥ 0.9 不在往堵的方向走); 达标的比占地小, 再比耗电小 (按 0.1MW 取整, 测量噪声不算理由), 再比档位 (低档便宜); 没达标的比产量高。
6. **走**: 换成最好的邻居; 没有更好的就停 (局部最优)。
7. **随机重启** (`--restarts N`, 默认 2; `--seed`): 再从 N 个随机起点各爬一次 (台数按机器速度换算; 抽到不合法的起点就重抽, 它的一步邻居多半也不合法)。最后取**所有实测过的** (含以前运行缓存的) 里最好的。

## 测量条件 (和数据集第三层一样)
沙盘阵营只解锁配方、**不做研究**: 四种机械臂每手都只抓 1 个 (实验 `inserter.hand-size-no-research` ✅, 箱子到箱子每分钟: 电力 52、高速 150、加长 75、集装 151), 所以快配方最先卡在机械臂上; 后期研究过的基地实际能做得更好: 全研究后每手 电力 / 高速 / 加长 4、集装 12、堆叠 16, 箱子到箱子每分钟 208 / 600 / 300 / 1812 / 2416 (实验 `inserter.hand-size-full-research` ✅)。按研究等级测加 `--research late` (全部科技研究完再测; 缓存按研究等级分开)。

## 结果
### 铁齿轮每分钟 600 (2026-11-02, 不限科技)
起点 (计算器: 组装机2型每台满速 90 → 7 台, 电力机械臂, 基础传送带) 实测只有 191 (30%), 每台只拿到约 54 块铁板 / 分钟 = 1 个电力机械臂的上限。爬山路线:

| 轮 | 改了什么 | 每分钟 | 占地 (格) | 耗电 MW |
|---|---|---|---|---|
| 0 | 起点: 组装机2型 7 台, 电力机械臂 × 1, 基础传送带 | 191 | 161 | 0.43 |
| 1 | 进料臂 → 高速机械臂 | 449 | 161 | 1.01 |
| 2 | 带子 → 高速传送带 (一道黄带每分钟 450, 两道铁板都要) | 572 | 161 | 1.29 |
| 3 | 每台进料臂 → 2 个 | 630 ✅ | 161 | 1.43 |
| 4 | 联动: 组装机3型, 台数 7 → 5 | 750 ✅ | 119 | 2.34 |
| 5 | 台数 → 4 | 600 ✅ | **98** | 1.88 |

最好: **组装机3型 4 台、每台 2 个高速机械臂进料 1 个出料、高速传送带, 单排**, 实测每分钟 600 (满速 4 × 150), 占地 98 格, 比没有联动邻居时停下的 161 格省 39%。共实测 92 个变体, 每个约 3~4 秒 (两次搜索各约 3 分钟)。同分的双排 2 × 2 台占地 104 格, 略大。

### 铁齿轮每分钟 600, 后期研究 (`--research late --restarts 3`, 2026-11-02)
没有重启时停在 组装机2型 7 台 + 1 个电力机械臂 + 高速传送带 (每分钟 593.5、161 格): 换组装机3型要同时加机械臂, 一步走不到。加随机重启后找到 **组装机3型 4 台、每台 2 个电力机械臂进料 1 个出料、高速传送带**: 每分钟 600、98 格、1.63MW —— 和不研究时的最好方案占地一样, 但研究后普通电力机械臂 (每手 4 个) 就够, 不用高速机械臂。实测 270 个变体。

## 限制和下一步
- 爬山 + 联动邻居 + 随机重启; 重启次数少时仍可能漏掉 (每次重启约 1~2 分钟); 再不够就换模拟退火。
- 只有组装机排一种积木; 流体原料的配方不支持; 链里中间品直塞 (例: 铜线直接塞电路板机) 还不支持 —— 下一块积木。
- 评测场 (sim): 把"配方 + 目标 + 允许的科技"写成考题, 搜索的最好成绩当基准, 给 AI 的方案打分。
